# 聊天上下文与缓存

聊天模式的请求依次包含原生系统人设、稳定功能说明与近期原文、本轮动态资料、当前消息及工具链。动态网页或成员资料变化只更新后面的资料节点，不改写前面的稳定窗口。

近期原文采用有界追加方式：默认以 8 条为裁剪基线，最多 16 条，记录仍受 4,000 字符预算约束。正文、说话人、时间、引用、附件引用及送达状态都保留，模型端通过固定字段顺序减少重复字段名。完整档案外置保存，具体旧事由当前账号、当前聊天范围内的历史工具检索。

本轮资料与工具结果在下一次正常互动退出输入；格式修复继续使用原互动的资料。人设、触发模式、主动发言和自然消息节奏沿用原配置。批次缓存只用于同一请求的幂等恢复，不跨用户消息复用固定回复。

功能说明的稳定性不构成工具授权。实际工具仍按本轮条件及现有权限规则提供，不强行固定全部工具列表。助手模式保持独立上下文。

旧安装在准备配置时，若完全没有 history 设置，会启用上述窗口默认值。已有明确的关闭、bounded 或 rolling 配置会保留。`wechat.history.windowStrategy` 可设为 `rolling` 停用追加；关闭 history 则回到兼容路径。

会话接口提供最近 20 次请求的分段摘要、变化部分、窗口重建原因、实际 Token 用量及请求结算耗时。摘要不包含原始聊天文本。分段变化不等于供应商的缓存边界，字符级回放收益也不等于实际费用节省。

验收同时检查未命中输入、每次互动调用数、延迟、格式修复率和接话质量。缓存由模型服务端决定，不以固定 90% 或 95% 命中率作为未经验证的保证。

验证命令：

```text
npm run test:history
npm test
npm run privacy:check
```

原始聊天档案和原生会话不属于代码回退范围，回退时应保留其最新数据。
