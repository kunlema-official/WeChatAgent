# 0.5.0-preview.2 Hook build fix

This patch addresses the Windows Actions failure where `scripts/build-hook.ps1` expected `src/inline_weixin_dll_load.cpp`, but the reviewed `mengyunqwq/wechat-hook` checkout no longer used that path.

Changes:

- Pin the Hook source to commit `e3f6cfc45701c5233d87024813ea8842aa7bfb4b`, the exact revision printed by the failed Actions run, so a moving upstream `main` cannot silently change the build inputs.
- Resolve the initialization translation unit by the HTTP server startup anchor if its filename moved; fail closed if the match is ambiguous.
- If `Route_SendVoiceMsg` is defined in `src/http_routes.cpp`, preserve that implementation in `src/voice_send_route.cpp` before replacing the route registrar. This prevents the build integration from accidentally overwriting the voice implementation.
- Upgrade `actions/checkout` and `actions/setup-node` to v5 to remove the Node.js 20 deprecation warning.
- Add static regression tests for source pinning, initialization-source discovery, route preservation, and workflow action versions.

Validation on the current Mac-side environment: 26 focused Node tests passed; source privacy scan passed. The Windows C++ build has not yet run after this fix. Real WeChat voice sending still requires the Windows Actions build and a separate live-client test.
