# DSH 离线与重连消息处理

DSH 退出、插件接口不可用或插件实例更换后，微信仍可接收消息。本项目默认保留聊天历史，但不把离线期间的旧闲聊逐条补答。

## 当前行为

- 桥接服务每两秒检查本机 DSH 插件，在模型请求与文字发送前再次确认。检查不调用模型。
- 离线期间的新消息仍写入聊天档案，调度缓冲标记为已跳过；重连后由新的微信消息触发回复。读取器晚到的旧事件同样检查恢复边界。
- 连接边界与插件实例标识保存在 `state/social-messages.json` 的 `dshConnection` 字段中，重启桥接不会重新放出已跳过的输入。首次升级会停止旧缓冲中尚未完成的历史批次，聊天记录继续保留。
- 旧模型结果在断连后晚到时不再发送；尚未发送的旧文字、配图草稿会取消。已提交部分保留原始送达记录，不自动重新提交，也不假定已经送达。
- 助手模式下，已登记而尚未完成的任务在 DSH 重启后进入中断待检查状态，包括排队任务。管理员可通过“任务列表”查看，并用现有“继续任务 T编号 补充要求”明确继续。
- 离线期间尚未被 DSH 接收的新任务仅保留为聊天资料，不会在重连时自动执行；恢复后请管理员重新发送请求。
- 新的请求携带插件实例标识。若插件在健康检查与提交之间重启，服务端在接收任务前拒绝旧实例请求，避免跨实例补交旧批次。

不会删除聊天档案、人格、表情、账号配置或 DSH 会话。离线旧消息可以作为后续接话的背景，但不属于当前执行授权。系统不会为每次断连向微信发送额外提示。

## 应用更新

更新桥接与 DSH 插件源码后，需要重启 WeChatAgent 后台并从托盘完整退出、重开 DSH，以加载实例标识和队列恢复规则。其他设备的旧安装包不会自动获得源码改动。

排查时可在 `state/logs/bridge.stdout.log` 查找 `connection=offline`、`connection=ready`、`replay=disabled` 和 `input_archived`。无需删除 `social-messages.json` 或清空 DSH 历史。
